# 蓝三字词表与词频

`lansan_guanfang.dict.yaml` 保留蓝三官方字词和编码，`ls_ci.dict.yaml` 保留此前合并使用的词表。合并后的公共词库为根目录 `lansan_merged.dict.yaml`。两份原表不作修改。

## 万象词频

词组排序采用 [amzxyz/rime-wanxiang-data](https://github.com/amzxyz/rime-wanxiang-data/tree/722eb52b5c233dbe136ffcb3942eee32d02082b4) 的固定版本 `722eb52b5c233dbe136ffcb3942eee32d02082b4`，作者为 amzxyz 及该项目贡献者。使用 `dicts/` 中的 `jichu`、`duoyin`、`diming`、`mingren`、`yiren` 五张词表；不导入万象拼音编码、语法模型或工具代码。

上游原创词库按 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 许可，完整文本随附在 [LICENSE.wanxiang](LICENSE.wanxiang)。适用范围见该版本的 [LICENSE-SCOPE.md](https://github.com/amzxyz/rime-wanxiang-data/blob/722eb52b5c233dbe136ffcb3942eee32d02082b4/LICENSE-SCOPE.md)。本仓库对数据的修改是：仅提取现有蓝三词组的词频，去掉拼音，同词多音或跨表重复时取最大权重。权重经过上游变换，不视为原始语料出现次数，也不相加。

`wanxiang_frequency.txt` 为可离线使用的提取结果（词条、上游权重两列），`wanxiang-source.json` 记录版本、输入文件及 SHA-256。现有公共词组共有 **167,902** 个（**167,943** 条词组编码记录），其中 **144,008** 个有万象显式权重，覆盖 **85.77%**；**23,894** 个未覆盖词仍然保留。缺少显式权重的上游记录不当作已覆盖。词频快照保留来源记录，用户排除词组不计入这些公共词库数量。

选择前也对照了白霜版本 `d6214cafa4aacf9c69d2d739d8af31d6c4614eb9` 的 `base`、`ext`、`tencent` 三表，覆盖 131,562 个现有词组（78.36%）。这只是对本仓库词组的覆盖率比较，不是输入法总体质量评测；最终没有混用白霜权重。

## 8105 规范字表

`tgh2013.txt` 从 [Unicode 17.0.0 Unihan.zip](https://www.unicode.org/Public/17.0.0/ucd/Unihan.zip) 的 [kTGH 属性](https://www.unicode.org/reports/tr38/#kTGH) 提取，按 2013 年《通用规范汉字表》序号排列，共 8105 个不重复汉字。一级为 3500 字、二级 3000 字、三级 1605 字；这里只使用是否收录，不把规范表序号或码表行号解释为字频。

固定下载地址、归档 SHA-256、提取结果 SHA-256 记录在 [tgh-source.json](tgh-source.json)，按 [Unicode License V3](LICENSE.unicode) 使用。修改仅为提取并按规范序号排列字形，不导入上游读音或其他属性。生成器离线核对字表校验值和字符数量。

## 拆分注释

用户提供 `蓝宝石_完整拆分表.tsv` 和 `蓝宝石_差异核对与字根表.xlsx`。原附件覆盖现有 92,841 个单字；前者包含仓库、修正、扩展试验三套拆分，后者提供字根键位及差异说明。这些是拆分分析结果，不是官方确认的字根序列。

导入时逐字核对附件全部编码与官方字表一致，优先选择修正版全码相符的 72,089 字；再用扩展试验版补充 10,224 字，避免其新增冲突覆盖原本匹配的修正版。每个选中条目还用工作簿“字根键位”及附件补码重新计算全码：四根以上取首、次、三、末根，其他字按所列补码拼接；“一”按附件的固定 `fjj` 例外处理。最终 **82,313 字**可显示，GB2312 全部 **6,763 字**覆盖。

- [decomposition.tsv](decomposition.tsv)：选中条目的字、全码、可显示字根、原始根 ID、补码键位及采用版本。
- [decomposition_roots.json](decomposition_roots.json)：工作簿字根键位，用于复算检查。
- [decomposition_unmatched.tsv](decomposition_unmatched.tsv)：10,528 个未采用条目，保留现有码、两版拆分及差异原因。含全码不符、PUA 映射不明、异常编码、仅有简码等情况。
- [decomposition-source.json](decomposition-source.json)：两份原附件及提取结果的 SHA-256、筛选规则、数量。原 58 MB TSV 和 XLSX 无需复制到运行目录。

`scripts/build_lansan_decomposition.py` 离线校验来源并生成 `opencc/lansan_cf.txt`。显示为“字根＋全码”，如 `摺〔扌习习白 · shhd〕`；以 `[旅字框]` 等名称显示特殊根，避免依赖私用区字根字体。不显示小码、识别码数字，不改变候选文本、次序或权重。`lua/lansan_decomposition_filter.lua` 将拆分追加到既有注释，保留拼音与反查编码；U 区及 U 编继续在后续过滤器追加。

沿用虎码的 `chaifen` 开关，Rime 选单显示“拆隐／拆显”，默认隐藏；输入时按 `Ctrl+J` 切换。普通编码、纯单字、简码及拼音反查均支持，多字词不加拆分。与虎码使用各自的 OpenCC 数据。

重新导入附件，或从仓库中的提取数据再生成：

```sh
python3 scripts/build_lansan_decomposition.py \
  --import-tsv /path/to/蓝宝石_完整拆分表.tsv \
  --root-workbook /path/to/蓝宝石_差异核对与字根表.xlsx

# 无需原附件；prepare.py、deploy.sh 也会执行此步
python3 scripts/build_lansan_decomposition.py
```

手机直接使用提交的 OpenCC 配置、文本表和 Lua 过滤器，无需原附件或生成脚本。更新时同步提交提取来源、校验信息及生成表。

## 当前排序规则

1. **GB2312 单字最简码不晚于第三选。** 按 GB2312 的 6,763 个汉字判断，多个等长最简码逐个保护。约束按全字集完整候选计算，常用集过滤后也不会超过第三。这是名次上限，不是保留旧首选、二选。
2. **有简码的长码在全部同码词后。** 不要求简码是首选或长码的前缀；前三选保护不应用于冗余长码。
3. **同码全部词组默认按万象词频降序。** 词可以跨过单字，旧官方分段不再限制词序。同频保持基线相对次序；未覆盖词使用低权重兜底，不代表测得了这些词的真实频率。[phrase_order_overrides.json](phrase_order_overrides.json) 中的明确词序优先于词频，目前为“护身、搜身”和“挂面、玉面”；实际与万象降序相反的只有后者。
4. **混输中表外字排在全部词后。** 使用完整 8105 规范字表，不以表内序号或行号推断频率。GB2312 最简码允许例外，以守住前三选；其具体位置由后续评议及明确例外决定。
5. **按明确评议安排字词位置。** [mixed_priority_reviews.json](mixed_priority_reviews.json) 保存 443 组评议：317 组词优先、126 组字优先。词优先将全部词尽量放到单字前，只在 GB2312 最简码前三选约束需要时插入单字；字优先保评议字首选，其他单字尽量放到词后。字内部、词内部顺序保持，非 GB2312 单字不额外限制为二选或三选。未列入评议的编码沿用基线位置。
6. **明确候选位置最后应用。** [candidate_prefix_overrides.json](candidate_prefix_overrides.json) 现有 6 组：翀首选、戳中次选；垚、郤首选；栐、瑄次选；摺首选。生成器检查字序、词序、GB2312 最简码前三选、长码及表外字后置，来源变化导致冲突时要求复核。
7. **纯单字原序保持。** 分层产生的 33 组混输字序变化，由 `lua/lansan_single_order.lua` 和过滤器在纯单字模式恢复。本次人工评议不改变单字内部顺序，恢复表无需新增条目。

## 历史基线与再生成方式

为使再生成可重复，脚本先重建提交 `1f0977f` 的调整前候选次序：

- 用旧官方字词位置分段，段内按万象权重排列；新增词在末个单字后。原表的 211,183 行未填写权重，同码原行序决定其位置。
- 初始词频使用“万象权重 + 1”，未覆盖词为 `1`；同频依次按旧 `ls_ci` 权重和原记录次序稳定排序。
- 应用 [char_word_order.json](char_word_order.json) 保存的历史 705 组、787 对评议，以及有简码的长码后置，得到基线。

这些步骤只确定起始位置和同频词的次序。随后移除用户排除词组，由 `apply_frequency_order` 全组重排词频、保护 GB2312 最简码前三选，再由 `apply_charset_order` 执行表外字后置并生成纯单字恢复表，由 `apply_reviewed_priorities` 应用字词优先评议，最后由 `apply_candidate_prefixes` 应用明确候选位置。**不会在词频重排后再次强制套用 705 组旧配对关系。** 例如“欺人先于泅”不再是最终排序的限制。

最终字词混合编码按候选次序写入 `N, N-1, …, 1`，让 `sort: by_weight` 准确落实位置。这些数是组内优先级，不是字频或词频；同词不同编码的最终权重可以不同。纯词组编码仍使用万象权重加一，纯单字编码保留原行内容。仅删除用户明确排除的词组，其余字词和编码保留，不导入外部字频；个人词库由可选本机入口接入，前三选保证针对公共词库。

## 再生成

日常准备或部署直接读取已提交的词频子集，无需网络。重新提取该固定版本的子集：

```sh
# 先将指定版本的上游数据仓库下载到本地；脚本校验五个文件的 SHA-256
python3 scripts/update_lansan_frequency.py --source-dir /path/to/rime-wanxiang-data
python3 scripts/prepare.py
```

更新上游版本时，同时更新 `wanxiang-source.json` 中的版本和各文件校验值，重新提取并生成公共词库，检查实际候选变化后提交来源信息、子集和公共生成表。手机直接部署源码中的生成表，不需要运行这些脚本。

重新提取固定版本的规范字表：

```sh
python3 scripts/update_lansan_tgh.py --unihan-zip /path/to/Unihan.zip
python3 scripts/merge_lansan_dicts.py
```

合并时会同时生成公共词库和 `lua/lansan_single_order.lua`，两者必须一起更新。指定 `--output` 导出到其他位置时，恢复表默认写在输出文件旁边，也可用 `--single-order-output` 指定路径。
