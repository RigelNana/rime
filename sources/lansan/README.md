# 蓝三字词表与词频

`lansan_guanfang.dict.yaml` 保留蓝三官方字词和编码，`ls_ci.dict.yaml` 保留此前合并使用的词表。合并后的公共词库为根目录 `lansan_merged.dict.yaml`。两份原表不作修改。

## 万象词频

词组排序采用 [amzxyz/rime-wanxiang-data](https://github.com/amzxyz/rime-wanxiang-data/tree/722eb52b5c233dbe136ffcb3942eee32d02082b4) 的固定版本 `722eb52b5c233dbe136ffcb3942eee32d02082b4`，作者为 amzxyz 及该项目贡献者。使用 `dicts/` 中的 `jichu`、`duoyin`、`diming`、`mingren`、`yiren` 五张词表；不导入万象拼音编码、语法模型或工具代码。

上游原创词库按 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 许可，完整文本随附在 [LICENSE.wanxiang](LICENSE.wanxiang)。适用范围见该版本的 [LICENSE-SCOPE.md](https://github.com/amzxyz/rime-wanxiang-data/blob/722eb52b5c233dbe136ffcb3942eee32d02082b4/LICENSE-SCOPE.md)。本仓库对数据的修改是：仅提取现有蓝三词组的词频，去掉拼音，同词多音或跨表重复时取最大权重。权重经过上游变换，不视为原始语料出现次数，也不相加。

`wanxiang_frequency.txt` 为可离线使用的提取结果（词条、上游权重两列），`wanxiang-source.json` 记录版本、输入文件及 SHA-256。现有公共词组共有 **167,902** 个（**167,943** 条词组编码记录），其中 **144,008** 个有万象显式权重，覆盖 **85.77%**；**23,894** 个未覆盖词仍然保留。缺少显式权重的上游记录不当作已覆盖。词频快照保留来源记录，用户排除词组不计入这些公共词库数量。

选择前也对照了白霜版本 `d6214cafa4aacf9c69d2d739d8af31d6c4614eb9` 的 `base`、`ext`、`tencent` 三表，覆盖 131,562 个现有词组（78.36%）。这只是对本仓库词组的覆盖率比较，不是输入法总体质量评测；最终没有混用白霜权重。

## 8105 规范字表

`tgh2013.txt` 从 [Unicode 17.0.0 Unihan.zip](https://www.unicode.org/Public/17.0.0/ucd/Unihan.zip) 的 [kTGH 属性](https://www.unicode.org/reports/tr38/#kTGH) 提取，按 2013 年《通用规范汉字表》序号排列，共 8105 个不重复汉字。一级为 3500 字、二级 3000 字、三级 1605 字；这里只使用是否收录，不把规范表序号或码表行号解释为字频。

固定下载地址、归档 SHA-256、提取结果 SHA-256 记录在 [tgh-source.json](tgh-source.json)，按 [Unicode License V3](LICENSE.unicode) 使用。修改仅为提取并按规范序号排列字形，不导入上游读音或其他属性。生成器离线核对字表校验值和字符数量。

## 当前排序规则

1. **保护 GB2312 单字的最简码前三选。** 按 GB2312 的 6,763 个汉字判断，检查字表中最短的普通字母编码；若有多个等长最简码，逐个保护。约束按全字集完整候选计算，常用集过滤后仍可见的字也不会超过第三。已有首选、二选位置尽量保留，不统一推到三选。
2. **有简码的长码仍后置。** 单字只要存在更短的普通字母编码，长码就在同码全部词组之后；不要求简码是首选或长码的前缀。前三选保护不应用于这种冗余长码。
3. **同码全部词组默认按万象词频降序。** 允许词跨过单字，旧官方的分段位置不再限制词序。同频词保持调整前的相对顺序；未覆盖词仍以低权重兜底，不额外交换同频词。用户指定的词序例外见 [phrase_order_overrides.json](phrase_order_overrides.json)，在不改变单字位置的前提下优先于词频。
4. **混输中表外字排在全部词后。** 在上述排序结果上，保留 8105 规范字及 GB2312 最简码的位置，将其余单字稳定移到同码所有词组之后。表外字之间、词组之间的相对顺序都不改变；GB2312 最简码即使不在 8105 表内也保留原位置，不统一降到第三。前三选与简码后置约束继续有效。
5. **纯单字原序保持不变。** 分层可能让规范字跨过表外字，改变混输中的单字相对位置；生成器将这些编码原来的字序写入 `lua/lansan_single_order.lua`。蓝三在纯单字过滤后用 `lansan_single_order_filter.lua` 恢复原序，对混输、其他方案和非码表候选不作调整。
6. **最后应用明确的字词优先例外。** [candidate_prefix_overrides.json](candidate_prefix_overrides.json) 指定少量候选前缀，其余候选按原次序跟随。生成器拒绝改变单字内部顺序、词组内部顺序、突破 GB2312 最简码前三选，或破坏表外字及有简码的长码后置规则；不存在的候选或来源变化导致的冲突必须复核，不静默忽略。

此前的前三选调整将四个字从四选提到三选：`afin` 泫、`oavv` 椹、`ofrm` 氇、`yeyw` 赅。2026.11.12.7 的 8105 分层调整 7,730 组字词顺序，并为 33 组保存纯单字恢复顺序。全字集 GB2312 最简码仍为 6,626 字首选、120 字次选、17 字三选，共 137 字需要选重；常用集隐藏軎、麴，可见 6,761 字中有 136 字需要选重。

例如 `admf` 从“漏、𥄪、漏雨、泪雨”变为“漏、漏雨、泪雨、𥄪”；`djar` 的“尿不湿”、`ucup` 的“加大力度”均从第七升至第二。所有词组内部次序保持。原先 345 个首选且有同码词的 GB2312 字全部仍为首选；其中 106 组排序变化，79 组的第一个词前移。另删除“脎”后的错词，该组不再与词同码。

例如 `alyw` 变为“法国人、河南人、泅、湖南人、欺人”，泅仍在第三；`ofrm` 变为“那一日、橹、氇、本日、栢……”，橹在第二、氇在第三。`tjvd` 的词序变为“魔石、磨石、磨……”，磨有简码 `tjv`，其全码继续位于词组之后。

用户指定例外：`syyr` 为“护身、搜身、摏”，搜身二选、摏三选。该编码的词组顺序明确为“护身、搜身”；词序例外必须完整列出该编码的全部有效词组，来源增删后脚本会报错提示复核。

2026.11.13.2 补充两组二选调整：`oivi` 为“本来以为、栐、素以”；`sifu` 为“挂面、瑄、玉面、揎”。`sifu` 先在词序例外中指定“挂面、玉面”，再由候选前缀将瑄放到第二。只有这组词序明确交换，其余同码词序保留；两组纯单字顺序不变。候选前缀例外现共 103 组。

2026.11.13.1 新增 101 组字词优先例外，依据用户列出的具体序号及后续答复，不将“三级字”自动视为全部词优先。原文标注的“85 组”实际列出 102 字、99 个编码：98 组只把原来的第一个词提到首选；`hhbm` 保留“翀、戳中、崌”。用户确认 `mnnm` 为“台口、筥、筶”，抢救项仅将 `iiif` 垚、`gynw` 郤升首选。其他抢救建议以及未列出的峣、藟、蹾维持现状。

例如 `atst` 为“海底捞、滧、𣵑”，`ronm` 为“电梯口、昫、最高领奖台、痀……”，`wegc` 为“视频教程、隩、𥜌、𩟇”。本轮没有删词、改码或改变词组内部顺序；常用集和全字集各恰好改变上述 101 组，纯单字全部候选保持原序。一级 3500 字及 GB2312 的最简码选位分布不变。

非 GB2312 的规范字中，最短码与词同码的仍有 324 字、316 组编码。本轮后其中 24 字首选、296 字前面有词，另 4 字前面只有其他单字。该范围不能等同于全部三级字：原 324 字中有 29 个二级字、295 个三级字。

## 历史基线与再生成方式

为使再生成可重复，脚本先重建提交 `1f0977f` 的调整前候选次序：

- 用旧官方字词位置分段，段内按万象权重排列；新增词在末个单字后。原表的 211,183 行未填写权重，同码原行序决定其位置。
- 初始词频使用“万象权重 + 1”，未覆盖词为 `1`；同频依次按旧 `ls_ci` 权重和原记录次序稳定排序。
- 应用 [char_word_order.json](char_word_order.json) 保存的历史 705 组、787 对评议，以及有简码的长码后置，得到基线。

这些步骤只确定起始位置和同频词的次序。随后移除用户排除词组，由 `apply_frequency_order` 全组重排词频、保护 GB2312 最简码前三选，再由 `apply_charset_order` 执行表外字后置并生成纯单字恢复表，最后由 `apply_candidate_prefixes` 应用当前明确的字词优先例外。**不会在词频重排后再次强制套用 705 组旧配对关系。** 例如“欺人先于泅”不再是最终排序的限制。

最终字词混合编码按候选次序写入 `N, N-1, …, 1`，让 `sort: by_weight` 准确落实位置。这些数是组内优先级，不是字频或词频；同词不同编码的最终权重可以不同。纯词组编码仍使用万象权重加一，纯单字编码保留原行内容。仅删除用户明确排除的词组，其余字词和编码保留，不导入外部字频；个人词库由可选本机入口接入，前三选保证针对公共词库。

## 再生成

日常准备或部署直接读取已提交的词频子集，无需网络。重新提取该固定版本的子集：

```sh
# 先将指定版本的上游数据仓库下载到本地；脚本校验五个文件的 SHA-256
python3 scripts/update_lansan_frequency.py --source-dir /path/to/rime-wanxiang-data
python3 scripts/prepare.py
```

更新上游版本时，同时更新 `wanxiang-source.json` 中的版本和各文件校验值，重新提取并生成公共词库，检查实际候选变化后提交来源信息、子集和公共生成表。手机直接部署源码中的生成表，不需要运行这些脚本。

重新提取固定版本的规范字表：

```sh
python3 scripts/update_lansan_tgh.py --unihan-zip /path/to/Unihan.zip
python3 scripts/merge_lansan_dicts.py
```

合并时会同时生成公共词库和 `lua/lansan_single_order.lua`，两者必须一起更新。指定 `--output` 导出到其他位置时，恢复表默认写在输出文件旁边，也可用 `--single-order-output` 指定路径。
